# RWKV-7 G1 2.9B Extreme Quantization V1

**Experimental weight-only checkpoint converter** preserving original RWKV-7 tensor names and shapes. This is not a native low-bit inference kernel, and it has **not** been validated on the full 2.9B checkpoint. The 700 MB target is a strict disk-archive budget, not VRAM at runtime. The architecture / recurrence must be supplied by the original RWKV-7 runner.

## Install

Python 3.10+, numpy, PyTorch 2.5+ (torch with CPU is sufficient for quantization, but substantial RAM is needed). The full RWKV-7 checkpoint is not bundled.

```bash
pip install numpy 'torch>=2.5'
python -m unittest discover -s tests -v
```

## Use

Download an authentic **G1 2.9B** `.pth` checkpoint from the official weights repository first. Use the `train_temp` / official RWKV-7 inference runner for compatibility validation.

```bash
python quant.py plan --checkpoint rwkv7-g1-2.9b.pth --out plan.json --budget-mb 700 --group-size 256 --sample 8192 --residual-rank 4
python quant.py pack --checkpoint rwkv7-g1-2.9b.pth --plan plan.json --out rwkv7-g1-2.9b-700mb.rwq
python quant.py verify --checkpoint rwkv7-g1-2.9b.pth --archive rwkv7-g1-2.9b-700mb.rwq --out reconstruction.json
python quant.py restore --archive rwkv7-g1-2.9b-700mb.rwq --out restored-fp16.pth
```

**The restored `.pth` becomes large again** and is meant to be loaded by the original engine. The compressed `.rwq` is not a drop-in model file for Albatross/rwkv.cpp. To run directly in <=700 MB storage/VRAM, a native 1-2-bit matmul kernel and a runtime are still required.

Plan: estimate per-matrix **sampled reconstruction error**, weighted by tensor role (heuristic, not an activation-calibrated loss), then greedy allocate 1/2/3/4/8 bits. Tiny tensors are kept FP16. Includes optional rank-4 approximations for `emb.weight` and `head.weight`, within reserved space. Metadata and scale overhead are counted; final archive is checked against the exact 700,000,000 byte limit. This can fail if even the minimum packing cannot fit. Use `--residual-rank 0` to disable low-rank components.

## Quality gates

1. Compare all restored weight shapes and reconstruction MSE via `quant.py verify`. A default relative MSE threshold **is not** evidence of acceptable language model performance.
2. Export token-aligned logits and labels from official FP16 original and restored quantized models, on held-out text, in NPZ files named `logits` and `labels`.
3. Evaluate with:

```bash
python eval_logits.py --ref reference_logits.npz --quant quantized_logits.npz --out quality.json --ppl-limit 1.05 --top1-limit 0.90
```

4. Repeat for multiple text domains and context lengths (1K, 4K, 16K and longer only if supported by the model/runner); measure state drift and end-to-end speed with the official inference engine. Do not claim task-quality parity before those tests pass.

## Limitations

- Sampling weights for reconstruction MSE is **not** activation sensitivity; proper second-order / GPTQ-type statistics and quality-aware budget allocation remain future work.
- Residual factors are generated by randomized range finding on selected matrices and may **worsen** final accuracy for some matrices; evaluate with/without factors.
- Current per-group format uses symmetric midrise uniform codebooks and FP16 scales; 1-bit models typically lose considerable quality without QAT/distillation.
- May require >16 GB host RAM; `torch.load(mmap=True, weights_only=True)` helps load lazily but serialization and factorization require temporary memory.
- No native packed-weight matmul yet; encoding is for storage, reversible decoding and benchmarking with existing RWKV inference implementation.
- For inference on original architecture: https://github.com/BlinkDL/RWKV-LM/tree/main/RWKV-v7 ; training reference: https://github.com/BlinkDL/RWKV-LM/tree/main/RWKV-v7/train_temp

## V1.1: Native low-bit CUDA matvec backend

`cuda_lowbit.py` provides an actual NVIDIA GPU Triton kernel which reads bitpacked
1/2/3/4/8-bit matrices in their original `.rwq` packing, decodes codes and scales
on-chip, and produces a matrix-vector product, with optional FP16 low-rank
residual correction. It does **not** unpack full weight matrices to FP16.

Requirements: NVIDIA CUDA-capable GPU, compatible PyTorch CUDA build, `triton`
(typically Linux; Windows may need WSL2), NumPy. Test on target hardware:

```sh
python -m pip install triton
python cuda_lowbit.py --selftest
```

From Python:

```python
import torch
from cuda_lowbit import LowBitArchive
archive=LowBitArchive('model-700mb.rwq')
x=torch.randn(archive.manifest['tensors']['blocks.0.ffn.key.weight']['shape'][1],device='cuda')
y=archive.matvec('blocks.0.ffn.key.weight',x)
```

**Scope limitation:** This is a native CUDA matrix-vector operator, *not* a
complete patched RWKV-7 autoregressive runtime. Integration into every RWKV-7
linear site, normalization, recurrent state updates, embedding and logits is
required for full token generation. No GPU is available in the build environment,
so GPU compilation and numerical parity have not been validated here.

## V1.1: Actual 2.9B quality evaluation harness

`real_model_eval.py` restores the packed weights, invokes your compatible
RWKV-7 generation runner twice (teacher and quantized), and calculates PPL
ratio + teacher-top1 agreement with `eval_logits.py`. Provide a module with:

```python
def evaluate(checkpoint_path: str, texts: list[str], output_npz: str) -> None:
    # Load exact RWKV-7 G1 2.9B architecture/tokenizer; use SAME tokens.
    # Save .npz with logits [T,V], labels [T], labels=-100 to ignore.
    # Use next-token aligned logits and labels; no shifted-label mismatch.
    ...
```

```sh
python real_model_eval.py \
  --original rwkv7-g1-2.9b.pth --archive model-700mb.rwq \
  --runner my_rwkv_runner:evaluate --texts heldout_texts.json
```

This tool is **not** itself the model runner, nor does it create evaluation
results without the real weights/hardware. A `ppl_ratio <= 1.05` is a testing
target, **not an achieved result**. Also measure long-context and real tasks
separately; the above measures logits-based likelihood/agreements only.
